# Embervoid 0.4.0 — performance on a dedicated server

PLAN R40.4b (closes R30.3). Measured with `python3 tools/server_check.py --perf --profile`; raw numbers in
`run/server-check/perf.json`, profile in `run/server-check/perf.jfr` (both regenerated by every run, not in git).

## Machine and setup

| | |
|---|---|
| Machine | Apple M1, 8 cores, 8 GB RAM, macOS 26.6.2 |
| Java | OpenJDK 17.0.20.1 (Homebrew), default heap (¼ of RAM = 2 GB), G1 |
| Server | `./gradlew runServerCheck` (Fabric dev server, Minecraft 1.20.1, Fabric API 0.92.12), fresh world, default config |
| Distances | view distance 10, simulation distance 10 |
| Load | load average 2.5 at the start, 1.2 at the end (nothing else running) |
| Run | 2026-10-22, commit on `claude/release-mp-318fa5` before merge; boot to "Done" 18 s |

Players are headless bots (`Bot` in the tool): real protocol clients that log in, answer keep-alives and teleports and
report their position every second, so the server ticks them as players (chunk tickets, natural spawning, mob
targets). They never move or hit back and cannot be hurt (Resistance V), so mobs and bosses keep attacking them.

**MSPT** = server tick time over the last 100 ticks (5 s), from `MinecraftServer.lastTickLengths`: mean, 95th
percentile and the longest tick. The budget is 50 ms.

## What the profile says

Java Flight Recorder (profile settings) over the whole 438 s run: 2948 server-thread samples, 5814 worldgen-worker
samples.

- **Server thread:** the mod's own code is in the top three frames of 0.5 % of the samples. Mob ticks are 12 % of
  the samples (`ReachMob.tick` and below), almost all of it vanilla movement, collision and AI under the mod's mobs;
  the Restless Bones (4.4 %) are simply the most numerous (natural spawns in the Necropolis). Per-tick checks in the
  mod (`ArenaManager.tick`, `BossFight.tick`, `ZoneTitles`, `MoonNightManager`, the hanging Thralls' player check)
  are each at or below 0.2 %.
- **Worldgen workers:** the mod's code is in the top three frames of 0.4 % of the samples; the largest are the
  terrain density functions (`ZoneBlend`, `CitadelTerrain`, both inside `interpolated`), arena placement and the
  realm features, each 1.4 % or less in total. The realm generates faster than vanilla terrain (49 chunks: ~1 s
  against 6.6 s for the overworld far from spawn), having no caves, ores or vanilla structures to place.
- **Spikes:** the single long ticks (69–92 ms) are G1 young-collection pauses (up to 86 ms in the same run, 2 GB
  default heap) on top of an ordinary tick; no mod code shows up in them. A server with more players should get a larger heap (`-Xmx4G` or more), as for any
  modded server.

**Hot spots fixed: none.** No mod method came near a share worth a change; every measured area, with and without a
player, and every boss fight stays far inside the 50 ms budget (worst realm mean 9.1 ms and p95 11.9 ms; the vanilla
overworld reference with a player: 9.6 ms and 12.6 ms). The candidates looked at and left as they are:

- Bosses re-path toward their target from `ReachBoss.mobTick` whenever the target changes block (vanilla's melee goal
  waits 4–11 ticks). With a walking player that is about as often as vanilla, and the fights above stay at 4–9 ms.
- Crypt Moths scan a 25×13×25 block cube for light every 2 s each: under 0.5 % of server samples with 6 moths.
- The fog wall draws up to 768 particle packets per player every 10 ticks on the largest arena (radius 48): network,
  not tick time.

## Not covered

- Players moving and fighting back: the bots stand still, so path recomputation, hits, abilities and phase changes
  under real play are not measured (the fights stay in their first phase; the Lord stays on the wall).
- Client-side frame time (rendering, GeckoLib models, fog) — no client may be launched here.
- More than three players, and a long-running server (chunk saving, region files growing).
- Run-to-run noise: an earlier run on the same machine under heavy load from other programs (load average 15–25)
  took 177 s to boot and hit the 60 s watchdog inside vanilla `/locate`, while the server thread waited for the
  region-file IO worker (fsync on macOS); the numbers above are from a quiet machine.
